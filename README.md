# Рядом — салоны и программа лояльности в MAX

Рабочий проект платформы салонов: личная запись клиента, «Живое окно» после отмен, оценки мастеров после завершённых визитов, кабинет сотрудников, CRM, оформление витрин, уведомления, обычная и партнёрская лояльность с настраиваемыми наградами и временные акции. Один бот MAX обслуживает несколько независимых салонов.

Интерфейс — React; сервер — NestJS/Fastify; данные — PostgreSQL; фоновые уведомления — Redis/BullMQ и отдельный worker. Всё запускается через Docker Compose. Для локального знакомства настоящий токен MAX не нужен.

## 1. Самый простой запуск: Docker

Нужен Docker Desktop в режиме Linux containers и достаточно свободного места на диске, где Docker хранит образы. Все команды выполняются из корневой папки проекта.

### Windows / PowerShell

```powershell
cd D:\projects\vscode\hackatons\max_hackaton
powershell -ExecutionPolicy Bypass -File .\ops\scripts\demo-up.ps1
```

Скрипт создаст `.env` из `.env.example`, если файла ещё нет, соберёт образы, запустит базу и очередь, применит миграции и заполнит демо-данные. Существующие салоны повторное заполнение не перезаписывает.

### Linux / macOS

```sh
sh ops/scripts/demo-up.sh
```

После успешного старта откройте **[http://localhost:8080](http://localhost:8080)**. Первый запуск дольше последующих: скачиваются образы и зависимости.

Ручной эквивалент:

```powershell
# Выполняйте копирование только при отсутствии .env
Copy-Item .env.example .env
docker compose --profile demo up --build -d
docker compose wait migrate seed
docker compose ps
```

## 1.1. Карта без обязательного API-ключа

Каталог использует MapLibre GL JS и бесплатные стили OpenFreeMap: ключ и счёт за просмотры не нужны. Для темы устройства или выбранной вручную темы загружается соответствующий светлый или тёмный стиль. Владелец салона может вручную найти адрес через Nominatim; ввод не отправляется автоматически при наборе текста, ответы кэшируются на сервере, незакэшированный поиск ограничен одним запросом в секунду на всё приложение. Миграция `011_map_provider_cache.sql` создаёт кэш и общий счётчик.

Публичный OpenFreeMap предоставляется без гарантии доступности. Если проекту понадобится договорный SLA или вырастет трафик, поменяйте `SALON_DISCOVERY_MAP_STYLE_LIGHT_URL` и `SALON_DISCOVERY_MAP_STYLE_DARK_URL` на свои совместимые MapLibre стили. Для замены геокодера измените `SALON_DISCOVERY_GEOCODER_PROVIDER` и настройки провайдера; `geoapify` требует ключа и соблюдения его бесплатных квот и атрибуции. Текст адреса передаётся выбранному геокодеру только после нажатия пользователем кнопки поиска.

У `migrate` и `seed` нормальное состояние — `Exited (0)`: это одноразовые задачи. `api`, `worker`, `postgres`, `redis`, `edge` должны продолжать работать. Проверка готовности: [http://localhost:8080/health/ready](http://localhost:8080/health/ready).

## 2. Что выбрать на экране входа

| Демо-роль | Что проверить |
|---|---|
| Клиент | Салоны, запись, перенос, отмена, «Живое окно», оценка мастера после визита, история, лояльность, купоны и настройки сообщений |
| Владелец · Линия | Каталог, мастера, графики, CRM, «Живое окно», программа лояльности, оформление и сотрудники салона A |
| Владелец · Точка | То же для салона B; согласование партнёрства с салоном A |
| Администратор | Работа с календарём, клиентами и каталогом салона «Линия» |
| Мастер | Только свои назначения, завершение визита и неявка |
| Новый владелец | Создание собственного салона с нуля |

После входа владелец или сотрудник выбирает свой салон в поле **«Пространство»**. Личный кабинет остаётся доступен тому же человеку. Назначенные роли проверяет сервер.

Демо-аккаунты и адреса вымышлены. В режиме `production` экран выбора ролей и выдача тестовых подписей отключены. Реальный вход происходит только через MAX.

## 3. Как работает бесплатное посещение

В демо включено правило **5 + 1** для основной услуги каждого салона. Владелец открывает рабочий кабинет → **«Лояльность»**. Для любой активной услуги можно включить программу и выбрать порог от 2 до 50 посещений.

Например:

1. Включить для «Стрижка и укладка» порог 5.
2. Клиент посещает эту услугу пять раз. После каждого фактического визита сотрудник нажимает **«Завершить визит»**.
3. После пятого завершения клиент получает право на одну бесплатную стрижку. Новый цикл начинается с нуля.
4. Клиент открывает личный кабинет → **«Лояльность»** → **«Записаться бесплатно»**, выбирает мастера и время.
5. В расчёте цена услуги полностью покрывается наградой; **к оплате — 0 ₽**.
6. При подтверждении награда резервируется. При завершении бесплатного визита — используется. При отмене или неявке — возвращается.

Счётчик ведётся **отдельно по услуге и салону**. Бесплатные визиты не дают новых отметок. Услуга с исходной нулевой ценой, отмена и неявка также не засчитываются. Платным здесь считается завершённый визит с положительной итоговой стоимостью: приложение не принимает деньги и не проверяет кассовый платёж.

История, завершённая до подключения механики, автоматически не пересчитывается. Порог нельзя менять после первой начисленной отметки; можно приостановить новые начисления, сохранив накопления. Полные правила исправлений и использования — в [описании функционала](docs/FUNCTIONALITY.md).

## 4. Где хранить настоящий токен MAX

**Рекомендуемый вариант для Docker:** создать файл `secrets/max_bot_token.txt` и вставить в него только токен одной строкой. Ни кавычки, ни `Bearer` не нужны. Затем использовать `compose.production.yaml` по [пошаговой инструкции MAX](docs/MAX-SETUP.md).

Для локального запуска сервер также поддерживает `MAX_BOT_TOKEN` в личном `.env` или `MAX_BOT_TOKEN_FILE` с путём к файлу. Настоящий токен не помещайте в `.env.example`, код React, URL или Git. Файлы `.env`, `.env.production` и содержимое `secrets/` исключены из Git и Docker build context.

Один токен используется сервером для проверки входа и worker для отправки сообщений. Клиентский браузер токен не получает. Для настоящего MAX нужны ещё публичный HTTPS-адрес, подключённое мини-приложение и webhook — одного токена недостаточно.

## 5. Запуск разработки без контейнера приложения

Нужны Node.js 20.11+ и работающие PostgreSQL/Redis. В Docker используются закреплённые версии образов из `compose.yaml`.

```powershell
# Один раз, если .env отсутствует
Copy-Item .env.example .env
npm ci

# Поднять только инфраструктуру с локальными портами
docker compose -f compose.yaml -f compose.dev.yaml up -d postgres redis
npm run db:migrate
npm run db:seed
npm run dev
```

Откройте **[http://localhost:5173](http://localhost:5173)**. Сервер работает на 3100, интерфейс проксирует API на этот порт. Для корректных локальных ссылок установите в `.env` `PUBLIC_APP_URL=http://localhost:5173` и перезапустите сервер.

Если порты уже заняты ранее запущенным экземпляром проекта, используйте его либо остановите именно старый экземпляр. Для второго независимого API задайте `PORT`, а интерфейсу — соответствующий `API_PROXY_TARGET`.

| Параметр / порт | Для чего |
|---|---|
| `APP_ENV=demo`, `MAX_MODE=mock` | Безопасное локальное демо без запросов к MAX |
| `MAX_BOT_NAME` | Имя бота без `@`, используется в ссылках |
| `PUBLIC_APP_URL` | Внешний адрес интерфейса; без завершающего `/` |
| `DATABASE_URL` | PostgreSQL для локальных процессов; Compose задаёт внутренний адрес сам |
| `REDIS_URL` | Redis для локального worker; по умолчанию `localhost:6380` |
| `STOREFRONT_THEMES_V2=true` | Включает безопасные темы, карточки, галерею и живой предпросмотр витрины |
| 8080 | Демо через Docker |
| 5173 / 3100 | Интерфейс / API при разработке |
| 5432 / 6380 | PostgreSQL / Redis только с `compose.dev.yaml`, доступны на loopback |
| 80 / 443 | Публичный сайт с HTTPS в production |

В базовом Compose база и Redis не публикуют свои порты наружу.

## 6. Проверки

```powershell
npm run typecheck
npm run build
npm run test:prepare
npm test
npm run api:docs
```

Интеграционные тесты работают с отдельной БД `salon_test` и очищают её перед каждым тестом. Они отказываются запускаться с именем базы без суффикса `_test`. Для другого подключения задайте `TEST_DATABASE_URL`; `test:prepare` требует права создания БД. `TEST_REDIS_URL` позволяет указать отдельный Redis.

Браузерные проверки при уже работающем локальном демо:

```powershell
npm run test:e2e
```

По умолчанию используется установленный Microsoft Edge, размеры desktop и Pixel 7. Можно задать `E2E_BROWSER_CHANNEL=chrome`, а `E2E_BASE_URL` — адрес демо. Отчёт сохраняется в `playwright-report/`, снимки — в `test-results/`.

OpenAPI также доступен через работающий сервер: `/api/openapi.json`. `docs/DATA-API.yaml` — собственная инвентаризация API, а не подтверждённый формат организаторов конкурса.

## 7. Остановка, обновление и данные

```powershell
# Логи
docker compose logs --tail=100 api worker migrate seed

# Остановить, сохранив базу, медиа и очередь
docker compose down

# Пересобрать после изменений исходников; миграции применятся автоматически
docker compose --profile demo up --build -d
docker compose wait migrate seed
```

Данные хранятся в Docker volumes `postgres`, `redis`, `media`; сертификаты — `caddy_data` и `caddy_config`. Удаление volumes удаляет данные. Для обычного обновления удалять их не нужно. Сохраните резервную копию PostgreSQL и медиа перед переносом или обновлением рабочего сервера.

## 8. Если что-то не запускается

| Симптом | Действие |
|---|---|
| Docker недоступен или команда зависает | Проверьте Docker Desktop, Linux containers и свободное место на системном диске; после освобождения места перезапустите Docker |
| `ENOSPC` | Освободите место или перенаправьте временные файлы по примеру ниже |
| `EADDRINUSE` | Указанный порт занят; проверьте уже работающий экземпляр проекта |
| Ошибка подключения PostgreSQL | Проверьте контейнер `postgres`, пароль и соответствие `DATABASE_URL` локальному/контейнерному запуску |
| Новые экраны выдают ошибку после обновления | Выполните миграции и перезапустите API; повторите `db:seed` в демо |
| `AUTH_REQUIRED` в настоящем MAX | Повторно откройте mini-app; сверьте токен именно его бота и время сервера |
| Запись создана, сообщение не пришло | Проверьте worker, запуск бота клиентом и согласия в профиле; запись не зависит от доставки |
| Нет свободных слотов | Проверьте назначение услуги мастеру, недельный график, исключения и занятые интервалы |

Если C: заполнен, а проект находится на D:, временные данные текущей PowerShell-сессии можно перенаправить так:

```powershell
New-Item -ItemType Directory -Force .local/tmp | Out-Null
$env:TEMP = (Resolve-Path .local/tmp).Path
$env:TMP = $env:TEMP
$env:npm_config_cache = Join-Path (Get-Location).Path '.local/npm-cache'
```

Это помогает сборке и тестам Node.js, но не переносит хранилище Docker и не освобождает системный диск.
