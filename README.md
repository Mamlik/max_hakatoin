# Рядом — салоны и программа лояльности в MAX

Рабочий проект платформы салонов: личная запись клиента, «Живое окно» после отмен, оценки мастеров после завершённых визитов, кабинет сотрудников, CRM, оформление витрин, уведомления, обычная и партнёрская лояльность с настраиваемыми наградами и временные акции. Один бот MAX обслуживает несколько независимых салонов.

Интерфейс — React; сервер — NestJS/Fastify; данные — PostgreSQL с PostGIS; карта — MapLibre GL JS; фоновые уведомления — Redis/BullMQ и отдельный worker. Всё запускается через Docker Compose. Для локального знакомства настоящий токен MAX не нужен.

## 1. Самый простой запуск: Docker

Нужен Docker Desktop в режиме Linux containers и достаточно свободного места на диске, где Docker хранит образы. Все команды выполняются из корневой папки проекта.

В `compose.yaml` база использует образ `postgis/postgis:17-3.5` с платформой `linux/amd64`. Расширение PostGIS необходимо для географического поиска; обычного PostgreSQL без установленного расширения недостаточно.

### Windows / PowerShell

```powershell
cd D:\projects\vscode\hackatons\max_hackaton
powershell -ExecutionPolicy Bypass -File .\ops\scripts\demo-up.ps1
```

Скрипт создаст `.env` из `.env.example`, если файла ещё нет, соберёт образы, запустит базу и очередь, применит миграции и заполнит демо-данные. Существующие салоны повторное заполнение не перезаписывает.

### Linux / macOS

```sh
sh ops/scripts/demo-up.sh
```

После успешного старта откройте **[http://localhost:8080](http://localhost:8080)**. Первый запуск дольше последующих: скачиваются образы и зависимости.

Ручной эквивалент:

```powershell
# Выполняйте копирование только при отсутствии .env
Copy-Item .env.example .env
docker compose --profile demo up --build -d
docker compose wait migrate seed
docker compose ps
```

У `migrate` и `seed` нормальное состояние — `Exited (0)`: это одноразовые задачи. `api`, `worker`, `postgres`, `redis`, `edge` должны продолжать работать. Проверка готовности: [http://localhost:8080/health/ready](http://localhost:8080/health/ready).

### Карта и поиск адреса

В конфигурации по умолчанию MapLibre загружает стили OpenFreeMap: `positron` для светлой темы и `fiord` для тёмной. API-ключ для этой конфигурации не требуется. Адреса стилей можно заменить через `SALON_DISCOVERY_MAP_STYLE_LIGHT_URL` и `SALON_DISCOVERY_MAP_STYLE_DARK_URL`. Для отображения карты нужен доступ к внешнему провайдеру; при ошибке загрузки поиск остаётся доступен списком.

Владелец может найти адрес через Nominatim кнопкой **«Найти адрес на карте»**, поставить или перетащить пин, либо ввести координаты вручную. Текст адреса передаётся геокодеру только по нажатию кнопки. Сервер кэширует ответы и ограничивает незакэшированные запросы к Nominatim одним запросом в секунду на всё приложение. Для альтернативного провайдера задайте `SALON_DISCOVERY_GEOCODER_PROVIDER=geoapify` и `SALON_DISCOVERY_GEOAPIFY_API_KEY`; геокодирование можно отключить отдельно от карты.

Миграция `011_map_provider_cache.sql` создаёт кэш и общий счётчик. Публичный OpenFreeMap предоставляется без гарантии доступности; при необходимости договорного SLA используйте свои совместимые MapLibre-стили. При подключении Geoapify учитывайте условия, квоты и атрибуцию провайдера.

## 2. Что выбрать на экране входа

| Демо-роль | Что проверить |
|---|---|
| Клиент | Салоны, запись, перенос, отмена, «Живое окно», оценка мастера после визита, история, лояльность, купоны и настройки сообщений |
| Владелец · Линия | Каталог, мастера, графики, CRM, «Живое окно», программа лояльности, оформление и сотрудники салона A |
| Владелец · Точка | То же для салона B; согласование партнёрства с салоном A |
| Администратор | Работа с календарём, клиентами и каталогом салона «Линия» |
| Мастер | Только свои назначения, завершение визита и неявка |
| Новый владелец | Создание собственного салона с нуля |

После входа владелец или сотрудник выбирает свой салон в поле **«Пространство»** на широком экране или в переключателе кабинета в мобильной шапке. Рабочие кабинеты также доступны из **«Профиля»**. Личный кабинет остаётся доступен тому же человеку. В мобильном демо пункт **«Сменить роль…»** возвращает на экран выбора аккаунта. Назначенные роли проверяет сервер; при отсутствии доступа к салону приложение возвращает в личные записи.

### Навигация в текущем интерфейсе

| Раздел | Что в нём доступно |
|---|---|
| **Мои места** | Знакомые и избранные салоны; каталог в режимах «Список» и «Карта», поиск по названию или услуге, фильтры и поиск рядом |
| **Карточка салона** | «Услуги и мастера», «Визиты», «Бонусы и акции»; запись и добавление в избранное |
| **Записи** | Вкладки «Ближайшие» и «История», фильтры по салону и дате, перенос, отмена и оценка завершённого визита |
| **Бонусы** | Прогресс своих программ, доступные награды и согласия на партнёрские версии |
| **Профиль** | Тема «Как в системе»/светлая/тёмная, общие настройки сообщений и рекламы с исключениями по салонам; выбор салона для согласия на купоны; события, предложения и «Живое окно» |
| **Рабочий календарь** | Выбор месяца и дня, фильтр всех/одного мастера с поиском, карточки и ручная запись; мастер видит только свои назначения |
| **Настройки салона** | Профиль, аватар, темы и карточки витрины, галерея, геоточка и ссылки, живой предпросмотр, сохранение и публикация, ссылка и QR-код |

На телефоне нижняя навигация содержит четыре основных раздела и кнопку **«Ещё»** для остальных пунктов, переключения пространства и темы. Выбранная тема сохраняется в браузере; режим **«Как в системе»** следует настройкам устройства. Время записи и рабочих графиков показывается в часовом поясе салона; фильтр даты личных записей учитывает часовой пояс каждого визита. В демо каталог содержит «Линию», «Точку» и дополнительные вымышленные салоны разных категорий.

### Поиск салонов и оформление витрины

Каталог поддерживает фильтры по направлению, услугам, городу, району, метро, цене, «Открыто сейчас», онлайн-записи и избранному. Поиск рядом запрашивает геопозицию устройства по действию клиента и учитывает выбранный радиус. На карте видны салоны с опубликованной геоточкой; карточка связана с выбранным маркером. Параметры фильтров и режима хранятся в URL.

Владелец выбирает тему **«Студия»**, **«Редакция»** или **«Нуар»**, режим оформления, акцент, варианты карточек услуг и мастеров, порядок разделов, галерею до восьми изображений и фокус обложки. Локальные изменения сразу видны в предпросмотре для телефона и широкого экрана. Публичная витрина обновляется после сохранения и публикации; аватар салона сохраняется отдельно и сразу. Произвольные CSS, HTML и JavaScript не поддерживаются.

### Сообщения и согласия

В профиле сервисные сообщения об изменениях записи, напоминания и предложения «Живого окна» включаются общими переключателями. Для каждой категории можно исключить отдельные салоны. Реклама имеет отдельное общее согласие и собственный список исключений. Worker проверяет актуальные настройки перед отправкой, включая сообщения, уже находящиеся в очереди.

Согласие на выдачу партнёрских купонов по салону и согласие на конкретную версию партнёрской программы настраиваются отдельно от рекламы. В mock-демо реальные сообщения MAX не отправляются.

Демо-аккаунты и адреса вымышлены. В режиме `production` экран выбора ролей и выдача тестовых подписей отключены. Реальный вход происходит только через MAX.

## 3. Лояльность, купоны и акции

В демо включено правило **5 + 1** для основной услуги каждого салона. Владелец открывает рабочий кабинет → **«Лояльность»** → **«Новая программа»**. Для активной услуги можно создать несколько независимых программ, выбрать порог от 2 до 50 платных посещений и награду: скидку в рублях, процент или одно/несколько бесплатных посещений. Период программы, срок награды и лимит выдачи настраиваются отдельно.

Например:

1. Включить для «Стрижка и укладка» порог 5.
2. Клиент посещает эту услугу пять раз. После каждого фактического визита сотрудник нажимает **«Завершить визит»**.
3. После пятого завершения клиент получает право на одну бесплатную стрижку. Новый цикл начинается с нуля.
4. Клиент открывает личный кабинет → **«Бонусы»** → **«Использовать награду»**, выбирает мастера и время.
5. В расчёте цена услуги полностью покрывается наградой; **к оплате — 0 ₽**.
6. При подтверждении награда резервируется. При завершении бесплатного визита — используется. При отмене или неявке — возвращается.

Счётчик ведётся **отдельно по программе, услуге и салону**. Один подходящий визит может дать отметку сразу в нескольких программах. Бесплатные визиты не дают новых отметок. Услуга с исходной нулевой ценой, отмена и неявка также не засчитываются. Платным здесь считается завершённый визит с положительной итоговой стоимостью, в том числе после скидки: приложение не принимает деньги и не проверяет кассовый платёж.

История, завершённая до подключения механики, автоматически не пересчитывается. После первой отметки условия программы закрепляются; для других условий создайте новую программу. Старую можно поставить на паузу или завершить, сохранив уже выданные награды.

### Партнёрские купоны и временные акции

В **«Партнёрствах»** владелец предлагает программу другому салону. Оба салона согласуют одну версию условий, а клиент отдельно подтверждает её в **«Бонусах»**. После подходящего платного визита выдаётся купон на услуги партнёра: фиксированная/процентная скидка либо пакет бесплатных посещений. Новая версия требует нового согласия.

Купон с несколькими бесплатными посещениями можно применить к нескольким отдельным записям в пределах доступного остатка. Каждая запись резервирует одно посещение; завершение списывает его, отмена или неявка освобождает резерв. Сервер проверяет остаток и защищает его от одновременного использования сверх лимита. Свободный купон владелец может отозвать с причиной; снятие выгоды с уже подтверждённой записи требует согласия клиента. После согласованного отзыва пакета новые резервы запрещаются, а остальные подтверждённые резервы сохраняются.

В **«Акциях»** владелец публикует скидку на свои услуги или предлагает её партнёру. Партнёрская акция появляется у клиента после подтверждения салоном-исполнителем. При записи клиент выбирает **одну выгоду**: обычную награду, партнёрский купон или акцию. Скидки не суммируются; итоговая цена показывается до подтверждения.

### Исправление исхода визита

Владелец может исправить завершённый визит или неявку через **«Исправить исход»** с обязательной причиной. Сервер проверяет связанные отметки, награды, купоны и лимиты акций. Зарезервированная или использованная награда от исходного визита может потребовать отдельного разбора. Восстановление прежнего партнёрского купона при исправлении на завершённый визит требует явного подтверждения владельца и доступного остатка; повторного списания уже использованного посещения не происходит. Если освободившийся лимит акции уже занят другой записью, исправление отклоняется. Исправление не выдаёт новые партнёрские купоны.

Подробные настройки — в [руководстве по лояльности и акциям](docs/loyalty-and-promotions-guide.md), базовые правила — в [описании функционала](docs/FUNCTIONALITY.md).

## 4. Где хранить настоящий токен MAX

**Рекомендуемый вариант для Docker:** создать файл `secrets/max_bot_token.txt` и вставить в него только токен одной строкой. Ни кавычки, ни `Bearer` не нужны. Затем использовать `compose.production.yaml` по [пошаговой инструкции MAX](docs/MAX-SETUP.md).

Для локального запуска сервер также поддерживает `MAX_BOT_TOKEN` в личном `.env` или `MAX_BOT_TOKEN_FILE` с путём к файлу. Настоящий токен не помещайте в `.env.example`, код React, URL или Git. Файлы `.env`, `.env.production` и содержимое `secrets/` исключены из Git и Docker build context.

Один токен используется сервером для проверки входа и worker для отправки сообщений. Клиентский браузер токен не получает. Для настоящего MAX нужны ещё публичный HTTPS-адрес, подключённое мини-приложение и webhook — одного токена недостаточно.

## 5. Запуск разработки без контейнера приложения

Нужны Node.js 20.11+, PostgreSQL с установленным PostGIS и работающий Redis. Учётная запись миграций должна иметь право создать расширение `postgis`. В Docker используются образы из `compose.yaml`.

```powershell
# Один раз, если .env отсутствует
Copy-Item .env.example .env
npm ci

# Поднять только инфраструктуру с локальными портами
docker compose -f compose.yaml -f compose.dev.yaml up -d postgres redis
npm run db:migrate
npm run db:seed
npm run dev
```

Откройте **[http://localhost:5173](http://localhost:5173)**. Сервер работает на 3100, интерфейс проксирует API на этот порт. Для корректных локальных ссылок установите в `.env` `PUBLIC_APP_URL=http://localhost:5173` и перезапустите сервер.

Если порты уже заняты ранее запущенным экземпляром проекта, используйте его либо остановите именно старый экземпляр. Для второго независимого API задайте `PORT`, а интерфейсу — соответствующий `API_PROXY_TARGET`.

| Параметр / порт | Для чего |
|---|---|
| `APP_ENV=demo`, `MAX_MODE=mock` | Безопасное локальное демо без запросов к MAX |
| `MAX_BOT_NAME` | Имя бота без `@`, используется в ссылках |
| `PUBLIC_APP_URL` | Внешний адрес интерфейса; без завершающего `/` |
| `DATABASE_URL` | PostgreSQL для локальных процессов; Compose задаёт внутренний адрес сам |
| `REDIS_URL` | Redis для локального worker; по умолчанию `localhost:6380` |
| `STOREFRONT_THEMES_V2` | Темы, варианты карточек, галерея и живой предпросмотр витрины; по умолчанию `true` |
| `SALON_DISCOVERY_SEARCH_ENABLED` / `SALON_DISCOVERY_MAP_ENABLED` / `SALON_DISCOVERY_EDITOR_ENABLED` | Поиск, карта и редактирование discovery-профиля; по умолчанию `true` |
| `SALON_DISCOVERY_MAP_STYLE_LIGHT_URL` / `SALON_DISCOVERY_MAP_STYLE_DARK_URL` | URL совместимых MapLibre-стилей для двух тем |
| `SALON_DISCOVERY_GEOCODER_ENABLED` / `SALON_DISCOVERY_GEOCODER_PROVIDER` | Поиск адреса; по умолчанию `true` и `nominatim` |
| `SALON_DISCOVERY_NOMINATIM_URL` / `SALON_DISCOVERY_GEOAPIFY_API_KEY` | Адрес Nominatim или серверный ключ Geoapify |
| `PLATFORM_ADMIN_MAX_IDS` | MAX user ID через запятую для проверки геоточек и ссылок платформой |
| 8080 | Демо через Docker |
| 5173 / 3100 | Интерфейс / API при разработке |
| 5432 / 6380 | PostgreSQL / Redis только с `compose.dev.yaml`, доступны на loopback |
| 80 / 443 | Публичный сайт с HTTPS в production |

В базовом Compose база и Redis не публикуют свои порты наружу.

## 6. Проверки

```powershell
npm run typecheck
npm run build
npm run test:prepare
npm test
npm run api:docs
```

Интеграционные тесты работают с отдельной БД `salon_test` и очищают её перед каждым тестом. Они отказываются запускаться с именем базы без суффикса `_test`. Для другого подключения задайте `TEST_DATABASE_URL`; `test:prepare` требует права создания БД. `TEST_REDIS_URL` позволяет указать отдельный Redis.

Браузерные проверки требуют уже работающего mock-демо с применёнными миграциями и демо-данными. По умолчанию они открывают `http://localhost:5173`:

```powershell
npm run test:e2e
```

Для демо через Docker укажите другой адрес:

```powershell
$env:E2E_BASE_URL = 'http://localhost:8080'
npm run test:e2e
```

По умолчанию используется установленный Microsoft Edge, размеры desktop и Pixel 7. Можно задать `E2E_BROWSER_CHANNEL=chrome`, а `E2E_BASE_URL` — адрес демо. Отчёт сохраняется в `playwright-report/`, снимки и трассировки ошибок — в `test-results/`.

Браузерные сценарии покрывают поиск и продолжение каталога, темы, настройки салонов, мобильное переключение кабинетов и ролей, вкладки записей, месячный календарь и права мастера, deep links, запись, оценки, «Живое окно», медиа и часовые пояса. Есть проверки сохранения несохранённых форм при сетевом сбое, клавиатурной навигации модального окна, запоздавшего расчёта цены после смены услуги, предпросмотра тем и карточек витрины и отображения на разных ширинах экрана. Проверка переключения месяца ожидает загрузки календаря перед проверкой дней.

Серверные и модульные тесты дополнительно проверяют остатки и конкурентные резервы наград/купонов, отзыв пакетов, исправления исходов, настройки уведомлений, поиск салонов, координаты и ссылки, геокодирование, адаптер карты и токены тем. Перечень сценариев описывает покрытие в исходниках; результат запуска зависит от окружения и должен проверяться командами выше.

OpenAPI также доступен через работающий сервер: `/api/openapi.json`. `docs/DATA-API.yaml` — собственная инвентаризация API, а не подтверждённый формат организаторов конкурса.

## 7. Остановка, обновление и данные

```powershell
# Логи
docker compose logs --tail=100 api worker migrate seed

# Остановить, сохранив базу, медиа и очередь
docker compose down

# Пересобрать после изменений исходников; миграции применятся автоматически
docker compose --profile demo up --build -d
docker compose wait migrate seed
```

При запуске через Docker миграции применяет сервис `migrate`; при запуске локальных процессов выполните `npm run db:migrate` перед перезапуском API и worker. В текущей версии миграции идут до **`011_map_provider_cache.sql`** включительно. Несколько файлов имеют одинаковый числовой префикс: мигратор учитывает полное имя файла и применяет все ещё не выполненные `.sql` в порядке сортировки.

Помимо исправлений остатков наград, отзыва и купонов-пакетов, добавлены `007_marketing_preferences.sql`, `008_notification_defaults.sql`, `009_global_notification_preferences.sql`, `010_salon_discovery.sql`, `010_storefront_customization.sql` и `011_map_provider_cache.sql`. Они вводят общие согласия и исключения, discovery-профили и геопоиск PostGIS, версию оформления витрины, кэш геокодера и общий ограничитель запросов.

При обновлении старой базы проверьте наличие PostGIS до миграции `010_salon_discovery.sql`. Для старого Docker volume используйте образ PostGIS, сохраняя данные и совместимую основную версию PostgreSQL; удаление volume для добавления расширения не требуется.

Данные хранятся в Docker volumes `postgres`, `redis`, `media`; сертификаты — `caddy_data` и `caddy_config`. Удаление volumes удаляет данные. Для обычного обновления удалять их не нужно. Сохраните резервную копию PostgreSQL и медиа перед переносом или обновлением рабочего сервера.

## 8. Если что-то не запускается

| Симптом | Действие |
|---|---|
| Docker недоступен или команда зависает | Проверьте Docker Desktop, Linux containers и свободное место на системном диске; после освобождения места перезапустите Docker |
| `ENOSPC` | Освободите место или перенаправьте временные файлы по примеру ниже |
| `EADDRINUSE` | Указанный порт занят; проверьте уже работающий экземпляр проекта |
| Ошибка подключения PostgreSQL | Проверьте контейнер `postgres`, пароль и соответствие `DATABASE_URL` локальному/контейнерному запуску |
| `extension "postgis" is not available` | Установите PostGIS для используемой версии PostgreSQL либо используйте образ из актуального `compose.yaml`; затем повторите миграции |
| Карта или поиск адреса недоступны | Проверьте флаги карты/геокодера, URL стилей и доступ к провайдеру; используйте список салонов или ручной ввод координат |
| Новые экраны выдают ошибку после обновления | Выполните миграции и перезапустите API; повторите `db:seed` в демо |
| `AUTH_REQUIRED` в настоящем MAX | Повторно откройте mini-app; сверьте токен именно его бота и время сервера |
| Запись создана, сообщение не пришло | Проверьте worker, запуск бота клиентом и согласия в профиле; запись не зависит от доставки |
| Нет свободных слотов | Проверьте назначение услуги мастеру, недельный график, исключения и занятые интервалы |

Если C: заполнен, а проект находится на D:, временные данные текущей PowerShell-сессии можно перенаправить так:

```powershell
New-Item -ItemType Directory -Force .local/tmp | Out-Null
$env:TEMP = (Resolve-Path .local/tmp).Path
$env:TMP = $env:TEMP
$env:npm_config_cache = Join-Path (Get-Location).Path '.local/npm-cache'
```

Это помогает сборке и тестам Node.js, но не переносит хранилище Docker и не освобождает системный диск.
