# Рядом — комплект дизайна

Откройте `index.html` для сравнения трёх концепций, `prototype.html` для сценариев и `guide.html` для мини-гайда. Файлы работают локально без сборки и без сервера. Это дизайн-прототип, не изменение приложения.

## Состав

- A «Тихий ритм»: спокойные карточки, постоянная нижняя навигация, крупные итоги. Рекомендуем развивать: клиенту проще найти главное действие, рабочие данные переходят в таблицы на широком экране.
- B «Линия дня»: крупная дата на витрине, вертикальная хронология и события вдоль линии. Преимущество — быстрый обзор дня; компромисс — каталогу услуг уделяется меньше внимания.
- C «Ясный кабинет»: каталожные вкладки, строки с границами и контекстные разделы. Преимущество — плотность и простая реализация; компромисс — более деловой клиентский опыт.
- У каждой концепции 7 обязательных экранов плюс отдельное пустое состояние выбора времени: 01, 02, 02b, 03, 04, 05, 06, 07.
- Для A добавлены подтверждение, записи и история, перенос, отказ, ошибки, лояльность, CRM, услуги, состояния и вход в кабинеты. Широкие календарь и CRM: 1440 × 900. Мобильные: 390 × 844.
- `svg/`: отдельные векторные исходники. `frames.json`: полный реестр. `text-layers.csv` и `.json`: каждый текст с ID, координатами baseline, размером, насыщенностью и цветом. `frames.js`: те же макеты для прототипа.

## Прототип

1. «Записаться» → стрижка → выбор мастера/времени → итоговая стоимость → подтверждение → «Мои записи».
2. «Нет подходящего времени» → запрос с редактируемыми условиями → согласие → запрос создан. В пульте демонстрации нажать «Пришло предложение» → принять или «Не подходит» → пропустить / изменить / закрыть. Варианты занятого слота и истечения срока выбираются отдельно в пульте.
3. «Хочу раньше» → будущая запись № 1042 → запрос переноса → предложение → перенос той же записи. В случае ошибки исходная запись сохраняется.
4. «Рабочий кабинет» → выбор рабочего пространства → «Окна» → цепочка → остановка с подтверждением → результат. Переключение кабинета — верхняя строка «Линия / …».

Пульт слева — только управление демонстрацией, не часть mini-app. Дата демо зафиксирована: 29 сентября 2026, 12:00, Москва. Проверка доступности имитируется; сервер не вызывается, сообщения не отправляются. Нижняя навигация и возврат работают в прототипе. Настоящую кнопку BackButton MAX должна подключить команда реализации.

## Референсы и выбор

Из [Linear](https://linear.app/) адаптированы: разделение навигации и содержимого, компактные подписанные статусы, цепочка событий. Из [Attio](https://attio.com/) — организация списка клиентов и отделение карточки клиента от табличного обзора. Проверены публичные страницы 28.09.2026. Это интерпретация подходов, не копия брендов или экранов.

Сравнение по ясности действий, плотности, мобильности и сложности — в `index.html`. Оценки экспертные, не результаты пользовательского теста. A сохраняет выразительность салона; B полезна для работы по расписанию; C удобна при большом объёме CRM. Для небольшого салона и MAX рекомендуем A.

## Передача в Figma

Целевой файл пользователя: https://www.figma.com/design/b4mc642ztBTJ6dgwk9vFZI/Untitled?node-id=0-1

Проверка доступа 28.09.2026: во встроенном браузере Codex файл показывает «Sign up or Log in». Авторизованный редактор недоступен. **Пробный импорт в Figma не выполнен**, доступность редактирования слоёв в Figma не подтверждена. Не считать этот комплект прошедшим финальный критерий Figma-импорта до проверки ниже.

1. Создайте страницы `01 — A Тихий ритм`, `02 — B Линия дня`, `03 — C Ясный кабинет`, `04 — A Сценарии`, `05 — A Desktop`, `06 — Компоненты`.
2. Сначала перетащите `svg/A-store.svg` на страницу A. Проверьте, что прямоугольники и декоративные линии доступны отдельно. Дважды нажмите на надпись «Линия» и попробуйте отредактировать текст.
3. В SVG текст хранится в `<text>`, но поведение импортера Figma не гарантируется: он может превратить текст в контуры. Если так произошло, восстановите текстовые слои по `text-layers.csv`. Координата Y в таблице — baseline, а не верх текстового блока.
4. Импортируйте остальные файлы по порядку `frames.json`, переименуйте фреймы по полю title. Отдельные SVG-группы не являются Figma-компонентами. Создайте компоненты Button, Field, BookingCard, Status, BottomNav, MAXChrome по мини-гайду и замените повторы экземплярами. Автолейаут и constraints задаются вручную.
5. Создайте стартовые точки «Клиент», «Живое окно», «Рабочий кабинет», соедините кнопки по маршрутам выше. SVG-ссылки не заменяют связи Figma Prototype. Для полей и выбранных состояний создайте варианты компонентов.
6. Проверьте 390 × 844 и 1440 × 900; подтвердите сохранение кириллицы, отсутствие наложений, доступ команды на просмотр и возможность передать права редактирования.

Шрифт: Arial, системный на Windows/macOS. Файлы шрифта не распространяются. Сведения и лицензирование: https://learn.microsoft.com/en-us/typography/font-list/arial . Если в команде нет Arial, согласовать замену и проверить переносы заново.

## Допущения и ограничения

- Демо существующего продукта доступно на localhost:8080; просмотрены вход и клиентская оболочка. Сценарии и ограничения изучены также по `apps/web/src/`, `docs/FUNCTIONALITY.md`, `docs/live-window-spec.md`. Не заявляется полный аудит действующего приложения.
- Данные вымышлены. ТЗ использует текущую программу 5 + 1; параллельные незавершённые изменения лояльности не включены в дизайн.
- Системные области MAX условны: верх 80 px, низ 24 px; перед реализацией измерить реальные safe area на целевых устройствах. Элементы управления от 44 px, основной текст 14–17 px.
- Мастер не получает CRM, цены, очередь или чужие назначения. Рабочие макеты здесь показывают администратора. Для мастера при реализации нужна отдельная сокращённая конфигурация.
- По одному окну активно только одно предложение. Остановка окна отзывает предложение, сохраняет запросы и не блокирует обычную запись. Запрос не резервирует слот. Перенос меняет существующую запись.
- HTML — ограниченный сценарный прототип, не хранилище записей: перезапуск маршрута сбрасывает демонстрационное состояние. Нет реального таймера, оплаты, сообщений и серверной проверки.
- Открытые вопросы: реальная высота MAX WebView; единый шрифт на устройствах команды; реальные обложки салонов; нужно ли показывать сводку предпочтений прямо в push; приоритет тестирования навигации с клиентами старшего возраста.
