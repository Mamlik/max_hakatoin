# ТЗ: поиск салонов, карта и расширенная публичная карточка

**Статус:** готово к декомпозиции
**Версия:** 1.0
**Связанные документы:** `docs/FUNCTIONALITY.md`, `docs/DATA-API.yaml`
**Область:** клиентский каталог и публичная витрина салона. Правила записи, CRM, купоны и лояльность не меняются.

## 1. Цель

Клиент должен быстро находить подходящий салон, а не просматривать общий список. Поиск работает одинаково в режиме списка и на карте: выбранные фильтры, сортировка и найденные салоны всегда совпадают.

Владелец салона должен управлять публичными данными, по которым его находят: точкой на карте, описанием, фото и проверенными ссылками на сайт, MAX и социальные сети. Он не получает возможность вставлять HTML, JavaScript, CSS или произвольные виджеты.

## 2. Границы первой поставки

### Входит в P0

- Единый экран «Салоны» с переключателем **Список / Карта**.
- Текстовый поиск, фильтры, сортировка, сохранение состояния в URL/startapp-параметрах.
- Поиск по текущей области карты, кластеризация точек, выбор салона на карте.
- Публичная карточка результата и полная витрина салона.
- Редактор публичного профиля салона для владельца и администратора, у которого уже есть доступ к витрине.
- Геоданные салона, проверка координат, безопасные ссылки и модерация публикации.
- Новые публичные API, миграции, аналитика и тесты из раздела 13.

### Не входит в P0

- Платное поднятие в выдаче. Результаты не покупаются и не смешиваются с рекламой.
- Отображение местоположения клиента другим пользователям или владельцам салона.
- Произвольный HTML, CSS, JavaScript, iframe, пиксели аналитики и сокращённые ссылки владельца.
- Фильтр по персональным партнёрским купонам: он мог бы раскрыть персональные условия клиента.
- Построение маршрута внутри приложения. Кнопка маршрута передаёт координаты во внешнее картографическое приложение.

## 3. Роли и доступ

| Действие | Гость / клиент | Владелец | Администратор с доступом к витрине | Платформенный администратор |
| --- | --- | --- | --- | --- |
| Искать и смотреть опубликованные салоны | Да | Да | Да | Да |
| Включить «рядом со мной» | Да, после согласия | Да | Да | Да |
| Редактировать публичный профиль своего салона | Нет | Да | Да | Да |
| Публиковать изменения | Нет | Да | По текущему правилу публикации | Да |
| Исправлять/подтверждать спорную геоточку и скрывать ссылку | Нет | Нет | Нет | Да |

Все проверки прав выполняются на сервере по tenant и текущей роли. Нельзя передать другой `tenantId` в теле запроса и отредактировать чужую витрину.

## 4. Публичный профиль и карточка салона

### 4.1. Данные, которые видит клиент

В выдаче и на карте показываются только опубликованные салоны. Минимальная карточка результата содержит:

- обложку или безопасный плейсхолдер;
- название, категорию и одну строку адреса;
- расстояние, если клиент передал точку;
- минимум активных цен (`от 1 500 ₽`) и до трёх совпавших услуг;
- статус «Открыт сейчас» / «Закрыт, откроется …» с учётом timezone салона;
- доступность онлайн-записи;
- кнопку «На карте» или «Маршрут» и кнопку открытия витрины.

Полная витрина дополнительно показывает описание, галерею, часы работы, карту с одной точкой, услуги, мастеров, безопасный агрегированный рейтинг по существующему правилу, контакты и ссылки владельца. Внутренние заметки CRM, телефоны клиентов, служебные поля, неопубликованные услуги и черновые ссылки не выдаются.

### 4.2. Данные, которые редактирует владелец

| Поле | Правило |
| --- | --- |
| Короткое описание | До 160 символов; используется в карточке и сниппете. |
| Полное описание | До 1 500 символов, простой текст с переносами строк. |
| Адрес и точка на карте | Адрес до 300 символов; координаты ставятся поиском адреса или перетаскиванием пина. |
| Район / метро | Выбираются из подсказок для выбранного города, максимум 3 станции. Не являются свободным текстом. |
| Галерея и обложка | По существующим правилам витрины: до 8 tenant-scoped изображений. |
| Ссылки | До 7 активных ссылок, в заданном порядке. Типы: `website`, `max`, `vk`, `telegram`, `instagram`, `tiktok`, `other`. |
| Признаки карточки | Показать карту, часы работы, галерею, рейтинг и ссылки. Цена и длительность услуг остаются обязательными. |

Ссылка состоит из `type`, `url`, необязательного `label` до 40 символов и `sortOrder`. URL принимается только с `https://`; после нормализации запрещаются `javascript:`, `data:`, встроенные учётные данные, IP-адреса, localhost и сокращатели ссылок. Для типа `max` допускается только утверждённый домен/диплинк MAX; для остальных типов домены сверяются с allowlist типа. `other` остаётся ссылкой `https` без иконки соцсети и проходит проверку модерации. В ответе API ссылки возвращаются только после публикации.

Редактор должен иметь предпросмотр desktop/mobile, локальный черновик, кнопку «Сохранить черновик» и отдельную кнопку «Опубликовать». Публикация требует заполненных названия, адреса, подтверждённой геоточки и хотя бы одной активной услуги. Изменение данных не должно автоматически менять публичную витрину до публикации.

## 5. Фильтры и поиск

### 5.1. Базовые правила

Фильтры объединяются через **И** между группами и через **ИЛИ** внутри одного множественного фильтра. Например, «маникюр или педикюр» + «открыт сейчас» + «до 3 км» вернёт салоны, подходящие всем трём условиям. Пустой фильтр не ограничивает результаты.

Все выбранные параметры хранятся в едином состоянии поиска. Переключение «Список / Карта», открытие карточки и возврат назад не сбрасывают их. Состояние сериализуется в URL/startapp без персональных данных; точные координаты пользователя туда не записываются.

### 5.2. Фильтры P0

| Группа | Поведение |
| --- | --- |
| Строка поиска | По названию, категории, опубликованному описанию, названию активной услуги, району и метро. Поиск без учёта регистра, `ё/е`, лишних пробелов и базовых форм слов. Запуск по Enter или через 350 мс после ввода. |
| Услуги и категории | Множественный выбор дерева «Категория → услуга». При выборе услуги результат обязан иметь активную опубликованную услугу. |
| Место | Город, район, метро, «рядом со мной» и радиус 1/3/5/10/25 км. Если геолокация недоступна, предложить город или адрес, но не показывать ложную дистанцию. |
| Цена | Минимальная и максимальная цена услуги. Если выбрана услуга — фильтруется её цена; иначе — минимальная цена среди активных услуг салона. Денежные значения передаются в minor units. |
| Время | «Открыт сейчас». Расчёт идёт на сервере по часовому поясу салона и расписанию с исключениями. |
| Запись | «Доступна онлайн-запись»: у салона есть хотя бы одна активная услуга и мастер с опубликованным расписанием. |
| Избранное | Только для авторизованного клиента; показывает его сохранённые салоны. |

После применения фильтра показываются активные чипы, число результатов и действие «Сбросить всё». Нажатие на чип снимает только этот фильтр. Если выборы стали противоречивыми, клиент видит ноль результатов, свои фильтры и действия «Увеличить радиус», «Очистить цену» или «Сбросить всё» — без самовольного изменения условий.

### 5.3. Фасеты и порядок фильтров

Сервер возвращает доступные значения и их количество **в контексте уже выбранных остальных фильтров**. Недоступные значения отключаются с понятной причиной, а не исчезают. Счётчики не должны учитывать черновые, архивные и непубличные салоны.

На мобильном фильтры открываются нижним листом: сначала строка поиска и быстрые чипы «Рядом», «Открыт сейчас», «Онлайн-запись», затем категории, место, цена и остальные параметры. Кнопка внизу показывает «Показать N салонов». На desktop панель фильтров остаётся видимой рядом со списком.

### 5.4. Сортировка

| Режим | Правило |
| --- | --- |
| Рекомендуемые | Текстовая релевантность, точное совпадение услуги, доступность онлайн-записи, полнота опубликованного профиля; затем стабильный `public_code`. Никаких платных коэффициентов. |
| Ближе | Расстояние по прямой; доступно только при точке клиента или центре выбранной локации. |
| Дешевле / дороже | Цена совпавшей услуги, иначе минимальная активная цена. Салоны без цены не попадают в этот режим. |
| По названию | Нормализованное название, затем `public_code`. |

Если пользователь ищет на карте, по умолчанию используется «Рекомендуемые». При выборе «Ближе» источник координат обязательно показывается текстом: «от вас» или «от центра района».

### 5.5. Следующая поставка (P1)

После стабилизации P0 добавляются: выбор даты и времени с фильтром по реально доступным слотам, фильтр «есть свободное окно сегодня», доступность конкретного мастера, сохранённые наборы фильтров и уведомление, когда в выбранной области появился подходящий салон. Эти возможности используют тот же поисковый контракт, но не должны ухудшать ответ P0.

## 6. Карта

### 6.1. Первый экран

Карта открывается в последнем выбранном городе, иначе в центре города из профиля клиента, иначе в городе из startapp. При согласии на геолокацию показывается отдельный маркер клиента; координаты используются только в памяти сессии. Карта не запрашивает разрешение сама: действие «Рядом со мной» инициирует запрос и объясняет цель.

На карте есть: строка поиска, кнопка фильтров с количеством, переключатель списка, кнопка текущего положения, кнопка «Искать в этой области» и выбранная сортировка. Все элементы доступны с клавиатуры и имеют текстовые подписи для screen reader.

### 6.2. Точки, кластеры и выбор

- В пределах одного экрана сервер возвращает максимум 500 точек. При большем количестве отдаёт кластеры с `count`, центром и границами.
- Кластер показывает число салонов; нажатие приближает карту к его границам. Нельзя раскрывать кластер в список, который не соответствует фильтрам.
- Одиночная точка показывает минимальную карточку: обложку, название, цену «от», состояние «открыт/закрыт», расстояние и кнопку «Открыть».
- Нажатие точки выделяет соответствующую карточку списка и прокручивает её в область видимости. Нажатие карточки списка выделяет точку и аккуратно центрирует карту, если точка вне экрана.
- Полная карточка открывается отдельным экраном/листом; возврат возвращает прежние фильтры, масштаб и выбранный объект.

### 6.3. Поиск в области

После заметного перемещения или изменения масштаба карта не меняет выдачу молча. Появляется кнопка «Искать в этой области». По её нажатию границы карты становятся фильтром `viewport`; список, точки и счётчик обновляются одним запросом. Пользователь может снять этот фильтр чипом «Область карты».

`viewport` и радиус могут использоваться одновременно: результат обязан попасть в обе геометрии. При выходе за пределы выбранного города карта предлагает расширить область или сменить город, но не подмешивает другой город неявно.

### 6.4. Выбор картографического провайдера

Текущая бесплатная связка: MapLibre GL JS для отрисовки и публичные стили OpenFreeMap для светлой/тёмной карты. Регистрация, API-ключ и оплата за показы карты не нужны; в настройках можно заменить оба URL на любой совместимый MapLibre style URL. Публичный OpenFreeMap работает без SLA и может быть отключён, поэтому интерфейс изолирован адаптером, а при ошибке карта не блокирует список.

Поиск адреса запускается только явным нажатием владельца салона и проходит через API приложения. По умолчанию используется публичный Nominatim: автодополнения нет, ответы кэшируются в PostgreSQL, а глобальная блокировка и метка времени ограничивают все экземпляры API одним незакэшированным запросом в секунду. Текст запроса не попадает в URL или кэш; ключ кэша — SHA-256 от провайдера, endpoint и нормализованного адреса. Для другого Nominatim-совместимого сервиса меняется только URL окружения. Опционально можно включить Geoapify Free, если нужен отдельный ключ и подходящий для запуска лимит.

Атрибуция карты остаётся видимой через контрол MapLibre; возле поиска показывается атрибуция геокодера. Тема карты переключается вместе с темой устройства или ручной настройкой приложения.

## 7. Модель данных и миграции

Источник истины для базового профиля остаётся `tenants`. Новые публичные поля не смешиваются с CRM и черновиком оформления.

### 7.1. Новые сущности

`salon_locations`

| Поле | Правило |
| --- | --- |
| `tenant_id` | PK/FK на `tenants`, один объект на салон. |
| `latitude`, `longitude` | `numeric(9,6)`, диапазоны `[-90;90]` и `[-180;180]`. |
| `address`, `city_id`, `district_id` | Нормализованный отображаемый адрес и справочники локации. |
| `metro_station_ids` | Связующая таблица `salon_location_metro`, максимум 3. |
| `geo_status` | `draft`, `pending`, `verified`, `rejected`; публична только `verified`. |
| `provider_place_id`, `geocoded_at` | Технические данные для повторной проверки, не публичные. |

`salon_discovery_profiles`

| Поле | Правило |
| --- | --- |
| `tenant_id` | PK/FK. |
| `short_description`, `description` | Ограничения из раздела 4.2. |
| `show_map`, `show_hours`, `show_gallery`, `show_rating`, `show_links` | Явные boolean, defaults соответствуют текущей публичной витрине. |
| `published_version`, `draft_version`, `updated_at` | Оптимистичная блокировка и разделение черновика/публикации. |

`salon_social_links`

| Поле | Правило |
| --- | --- |
| `id`, `tenant_id`, `kind`, `url`, `label`, `sort_order` | Составляют опубликованный набор ссылок. |
| `is_published`, `validation_status`, `rejection_reason` | Черновая и небезопасная ссылка не выходит в public API. |

Для пространственного поиска используется PostGIS: `geography(Point, 4326)` и GiST-индекс. Индексы также нужны на опубликованный статус, `city_id`, активные услуги и нормализованный поисковый вектор. В миграции должна быть проверка расширения, backfill только для координат, прошедших валидацию, и обратимый безопасный rollback. До появления подтверждённой точки салон остаётся в списковом поиске по городу/адресу, но на карту не попадает.

## 8. API-контракт

Все маршруты имеют префикс `/api/v1`. Точные Zod-схемы добавляются в `packages/contracts`; UI не дублирует правила валидации.

### 8.1. Публичное обнаружение

`GET /public/salons/discover`

Параметры: `q`, `categoryIds[]`, `serviceIds[]`, `cityId`, `districtIds[]`, `metroIds[]`, `lat`, `lng`, `radiusKm`, `viewport=west,south,east,north`, `minPriceMinor`, `maxPriceMinor`, `openNow`, `onlineBooking`, `favoritesOnly`, `sort`, `cursor`, `limit`, `mode=list|map`.

`limit` ограничен: 20 для списка, 500 точек для карты. Неверные сочетания (`favoritesOnly` без сессии, частичная пара `lat/lng`, некорректные границы, отрицательная цена) возвращают `400` с кодом поля. Ответ содержит `items`, `clusters` (только для карты), `nextCursor`, `totalApprox`, `appliedFilters` и `facets`. В каждой map-точке есть только публичные `publicCode`, координаты и короткая карточка; контактные данные не дублируются.

`GET /public/salons/discover/facets` принимает те же фильтры без pagination и возвращает только доступные клиенту фасеты с количеством. Кэшируется отдельно от результатов.

`GET /public/salons/:code` расширяется блоком `discoveryProfile`, `location`, `socialLinks`. Старые поля и текущий контракт каталога сохраняются, чтобы не сломать существующие клиенты.

### 8.2. Кабинет салона

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/work/:t/storefront/draft` | Существующий маршрут: в ответ добавляется `discovery`, содержащий черновик профиля, геоточку и ссылки. |
| `PUT` | `/work/:t/storefront/draft` | Существующий маршрут: сохраняет `discovery` вместе с остальным черновиком витрины и `expectedVersion`. |
| `POST` | `/work/:t/storefront/validate-location` | Новый маршрут: проверить адрес/пин, вернуть нормализованный адрес и статус. |
| `POST` | `/work/:t/storefront/publish` | Существующий маршрут: публикует сохранённую версию после полной проверки. |

Конфликт версии возвращает `409` с актуальной версией и списком изменённых полей. Все изменения и публикации записываются в audit log: actor, tenant, действие, версия, без хранения точной геопозиции клиента.

## 9. Серверная обработка поиска

1. Сначала ограничить запрос опубликованными и неархивными tenant.
2. Применить структурные фильтры услуг, цены, графика, города/района/метро и избранного.
3. Применить геометрию: `ST_DWithin` для радиуса, пересечение точки с viewport для области карты.
4. Для текста использовать нормализованный поисковый вектор и безопасный параметризованный запрос; пользовательский ввод никогда не попадает в SQL-строку.
5. Вычислить расстояние и доступность только после геофильтра; округлять расстояние в ответе (метры до 1 км, далее 0,1 км).
6. Применить сортировку, стабильный tie-breaker и cursor-pagination. Offset для большой выдачи не использовать.

Проверка «Открыт сейчас» использует интервалы расписания и исключения, а не упрощённое поле `is_open`. Услуга считается доступной для фильтра, только если она опубликована, активна и имеет цену в нужной валюте.

## 10. UX, ошибки и доступность

- Карта не является единственным способом найти салон: любой результат доступен списком и с клавиатуры.
- Загрузка карты не блокирует поиск и список. Показываются skeleton, затем текст ошибки с кнопкой повторить.
- При недоступной геолокации или отклонённом разрешении фильтры города, района и адреса работают полностью.
- При недоступном провайдере карты сохраняется список и строка «Карта временно недоступна»; у салона остаётся кнопка открытия адреса во внешней карте.
- В списке и попапе карты изображения имеют осмысленный `alt`; интерактивные пины доступны по tab/стрелкам и имеют читаемое название салона.
- Не публиковать точный адрес, если владелец не подтвердил `show_map`; такой салон можно находить в списке только по городу/району, без пина и маршрута.

## 11. Аналитика и приватность

События: `salon_discovery_opened`, `search_submitted`, `filter_changed`, `map_area_search`, `map_marker_selected`, `salon_card_opened`, `route_opened`, `booking_started_from_discovery`, `profile_draft_saved`, `profile_published`, `social_link_opened`.

В аналитику передаются идентификаторы фильтров, город и диапазон расстояния, но не сырые текстовые запросы без обезличивания и не точные координаты клиента. Точные координаты используются для ответа текущей сессии и не сохраняются в профиле клиента без отдельного согласия.

## 12. Производительность и эксплуатация

- P95 ответа списка и фасетов — до 1,5 с при 10 000 опубликованных салонов; P95 ответа карты — до 2 с без учёта тайлов провайдера.
- Поиск после набора текста отменяет предыдущий запрос; UI применяет ответ только для актуального набора фильтров.
- Результаты и фасеты кэшируются по нормализованным публичным фильтрам. Персональное избранное и координаты клиента в общий кэш не попадают.
- Ограничение частоты: поиск и фасеты — отдельные лимиты, запросы геокодирования — более строгие. Ошибка лимита возвращает понятный `429`.
- Наблюдаемость: latency по режимам list/map, пустые выдачи, ошибки карт SDK, геокодирования и публикации, количество кластеров, конверсия до записи.

## 13. Критерии приёмки

1. При одинаковых фильтрах список и карта возвращают один и тот же набор `publicCode`.
2. Смена режима, открытие карточки и возврат сохраняют фильтры, сортировку, выбранный салон и область карты.
3. Салон без `geo_status=verified` не отображается точкой на карте.
4. Перемещение карты не меняет выдачу до нажатия «Искать в этой области».
5. Кластер приближает карту и после приближения показывает только точки, удовлетворяющие текущим фильтрам.
6. Выбор точки выделяет карточку списка, а выбор карточки выделяет точку.
7. «Рядом со мной» запрашивает разрешение только по действию пользователя; отказ не ломает каталог.
8. Фильтр «Открыт сейчас» корректно учитывает timezone, перерывы и исключения в расписании.
9. Фильтр по цене использует цену выбранной услуги, а без услуги — минимальную активную цену салона.
10. `favoritesOnly` без авторизации возвращает явную ошибку, без утечки избранного другого клиента.
11. Ссылка `javascript:`, `data:`, localhost, сокращатель или домен не своего типа не сохраняется и возвращает ошибку конкретного поля.
12. Черновые описание, координаты и ссылки не попадают в public endpoint до публикации.
13. Владелец другого tenant получает `403` при попытке прочитать или изменить чужой черновик.
14. Конкурентное сохранение профиля даёт `409`, а не затирает чужие изменения.
15. При отключённой карте пользователь может выполнить весь путь поиска и открыть витрину через список.
16. Есть unit-тесты схем URL и геометрических границ, интеграционные тесты API/прав/публикации и e2e-сценарии: список → фильтр → карта → точка → витрина → начало записи.
17. Новые миграции применяются на чистой БД и на текущей БД без потери опубликованных витрин; обратимость проверена.

## 14. Декомпозиция работ

1. **Контракты и БД:** справочники локаций, PostGIS, миграции, публичный профиль и ссылки, аудит.
2. **Поисковый backend:** discover/facets, индексирование, курсоры, права, лимиты, тестовые фикстуры.
3. **Карта:** `MapAdapter`, загрузка SDK, кластеры, viewport, fallback и accessibility.
4. **Клиентский каталог:** единое состояние, фильтр-лист, список, синхронизация с картой, пустые состояния.
5. **Кабинет владельца:** черновик, редактор локации, ссылки, предпросмотр, проверка и публикация.
6. **Качество и запуск:** метрики, feature flag `salonDiscoveryMap`, нагрузочное тестирование, миграционный прогон и поэтапное включение по городам.

Флаг включается отдельно для публичного поиска, карты и редактора локаций. Откат скрывает новые интерфейсы, но не удаляет введённые данные и не ломает текущий список `/public/salons`.
